# PAX Fix для BIFIT Kassa

Текущая версия: `0.4.0`. Старая версия `0.1.0` признана
непригодной для реального запуска и должна быть удалена или заменена при
полностью закрытом приложении.

Отдельный JAR, который не изменяет штатные `rr-electro.jar` и `inpas-win.jar`.
Он добавляет два связанных варианта оборудования:

* `INPAS PAX Fix (slip bridge)` — без изменений передаёт оплату, возврат,
  отмену, сверку и отчёты штатному INPAS. После его ответа регистрирует только
  SHA-256 конкретного слипа в оперативной памяти. Собственного запуска
  DualConnector и собственной обработки его файлов нет;
* `RRElectro PAX Fix (cut/feed)` — выполняет все операции через штатный
  RRElectro. Только при совпадении зарегистрированного хеша печатает документ
  одной последовательностью `Wait → Print(48) → Feed(15) → Cut → Wait`. Оба
  `WaitForPrinting` делят один общий 30-секундный бюджет. Все остальные
  документы безусловно передаются штатному методу без изменений.

## Сборка

Сборка и все локальные тесты:

```powershell
powershell -NoProfile -File .\build.ps1
```

Результат: `dist\pax-fix.jar`.

## Подключение

После установки и перезапуска приложения:

1. В настройках ККТ добавить/выбрать `RRElectro PAX Fix (cut/feed)` и перенести в
   него те же параметры подключения, что использует штатный RRElectro.
2. В платёжных терминалах добавить/выбрать `INPAS PAX Fix (slip bridge)` и
   перенести параметры штатного INPAS.
3. Выполнить тестовую операцию на стенде: проверить две копии банковского слипа,
   ширину колонок, нижнее поле и положение отрезки.

Откат: снова выбрать штатные INPAS и RRElectro. Оригинальные JAR остаются
нетронутыми.

## Ограничения

* Плагин зависит от публичных классов конкретных версий `rr-electro` 1.9 и
  `inpas-win` 1.6. После их обновления сборку и smoke-тест нужно повторить.
* Размер самих букв задаётся шрифтом/таблицами РР-01Ф; плагин меняет разметку
  структурированного слипа на 48 колонок.
* Значения 48 колонок для INPAS и 15 строк для RRElectro выбраны специально для
  текущей конфигурации с 80-мм лентой.
* Терминальная обёртка не исправляет и не меняет поведение штатного INPAS,
  включая его запуск DualConnector и ожидание ответа. Это сознательно оставлено
  вне задачи исправления печати.

## 0.4.0

* Удалён собственный запуск DualConnector, ожидание `result.txt`/`receipt.txt`,
  таймауты банковских операций и завершение процессов.
* INPAS-компонент оставлен только как мост хеша слипа к печатному компоненту.
* Исправление применяется в RR-Electro только к слипу, который вернул штатный
  INPAS; прочие документы печатаются штатным методом.

## 0.3.1

* `RRElectroPaxFix`: внутреннее поле `driver` ищется лениво; если поле недоступно
  (обновление `rr-electro`), документ печатается штатным `RRElectro` — старт
  приложения больше не зависит от рефлексии.
* Ширина печати и протяжка вынесены в параметры устройства: `printWidth`
  (20–80, по умолчанию 48) и `feedLines` (0–40, по умолчанию 15).
